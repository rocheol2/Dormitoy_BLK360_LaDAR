## 0. 먼저 확인할 것

**새 코드를 작성할 필요는 없다.** 필요한 스크립트가 모두 있다.

| 스크립트 | 용도 |
|---|---|
| `make_mesh_poisson.py` | 메시 생성 (Screened Poisson). **기본으로 이걸 쓴다** |
| `make_mesh.py` | 메시 생성 (SDF + 마칭 큐브). 해상도는 `--voxel` |
| `compare_mesh.py` | 두 방식의 정확도·완전성 비교 |
| `register_dorm_v4.py` | 정합·병합 |

### 지금 있는 5cm 판을 다시 만들 이유가 있는가

| | 현재 파일 (2026-08-01 생성) | 지금 코드로 재생성 시 |
|---|---|---|
| 형상·색상 품질 | 동일 | 동일 |
| 생성 시간 | 2시간 21분 | 약 30분 |
| `is_winding_consistent` | **True** | **False** |

재생성하면 빨라지지만 **감김 일관성을 잃는다.** 현재 5cm 본체는 감김 보정
(40분)을 거쳐 만들어졌고, 지금은 그 단계가 기본에서 빠져 있기 때문이다.
보이는 차이는 거의 없지만 위상이 중요한 용도라면 현재 파일이 낫다.

→ **결론: 시간이 급하지 않다면 지금 파일을 그대로 쓰는 편이 낫다.**
굳이 재생성한다면 `--fix-winding`을 함께 주어 동등한 결과를 얻는다.

## 1. 재실행 방법

```bash
cd "04_처리스크립트"
PY="e:/Data/LiDAR/2026.01 403호 촬영/venv_lidar/Scripts/python.exe"
```

### 정합 (점군)

```bash
"$PY" register_dorm_v4.py                                # 전체, 약 2시간
"$PY" register_dorm_v4.py --only-group B --min-fit 0.12  # 별동만, 약 6분
```

### 메시 — Poisson (권장)

```bash
"$PY" make_mesh_poisson.py --group main  --depth 13 --support 0.05   # 33분
"$PY" make_mesh_poisson.py --group annex --depth 13 --support 0.05   # 7분
```

**`--trim`(밀도 백분위)은 켜지 말 것.** LiDAR 는 원거리일수록 점밀도가 낮아
정상적인 면까지 잘려 큰 구멍이 생긴다. `--support`(거리 기준)를 쓴다.

### 메시 — 마칭 큐브

```bash
"$PY" make_mesh.py --group main  --voxel 0.02 --suffix _2cm   # 본체 2cm, 2시간
"$PY" make_mesh.py --group main  --voxel 0.05                 # 본체 5cm, 약 30분
"$PY" make_mesh.py --group annex --voxel 0.02 --suffix _2cm   # 별동 2cm, 17분
"$PY" make_mesh.py --group annex --voxel 0.05                 # 별동 5cm, 약 5분
```

> 출력 파일명이 겹치면 **덮어쓴다.** 기존 판을 남기려면 `--suffix`를 주거나
> 먼저 백업할 것.

한 시간을 넘기는 작업은 백그라운드로 돌리고 로그를 남기는 편이 좋다.

```bash
"$PY" -u make_mesh.py --group main --voxel 0.02 --suffix _2cm > 로그/mesh_main_2cm.log 2>&1 &
```

Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8`을 앞에 붙인다.

## 2. 파라미터 정하는 법

| 옵션 | 기본값 | 정하는 기준 |
|---|---|---|
| `--voxel` | 0.05 | 메시 해상도. **2cm 아래로 내리지 말 것** (§3) |
| `--support` | voxel×2 | 이보다 먼 표면은 잘라냄. 키우면 구멍이 줄지만 없는 면이 생김 |
| `--trunc` | voxel×3 | SDF 절단거리. 얇은 벽에서 키우면 양면이 뭉침 |
| `--block` | 64 | 크게 하면 블록 수↓ 블록당 메모리↑. 메모리 부족 시 32로 |
| `--min-component-faces` | 500 | 부유 노이즈 제거. 작은 실물(난간 등)이 지워지면 낮출 것 |
| `--clean-radius` / `--clean-min-neighbors` | 0.30 / 8 | 고립점 제거. 원거리 노이즈가 남으면 강화 |
| `--fix-winding` | 꺼짐 | 위상이 중요할 때만. 1,185만 면에 40분 |

## 3. 넘지 말아야 할 선

**2cm보다 잘게 만들지 말 것.**

원해상도 점간격은 별동 2.08mm / 본체 5.60mm로 충분히 조밀하다. 그러나
**정합 정확도가 본체 2.6cm / 별동 7.0cm**다. 같은 벽을 찍은 서로 다른 스캔의
점들이 이미 그만큼 어긋나 있다는 뜻이라, 격자를 그보다 잘게 하면 정밀해지는 게
아니라 **정합 오차가 표면의 요철로 조각된다.**

더 정밀한 결과가 필요하면 해상도를 올릴 게 아니라

1. 정합을 개선하거나 (본체는 이미 한계에 가깝다)
2. **재촬영한다** — 특히 별동은 스캔 3개뿐이라 정합 정확도 7.0cm가 한계다.
   해당 구역 스캔 추가가 유일하고 확실한 개선책이다.

## 4. 코드를 새로 짠다면 반드시 지킬 것

`make_mesh.py`를 다시 만들거나 다른 도구로 옮길 때, 아래는 시행착오로 얻은
것들이라 모르면 같은 함정에 빠진다. 자세한 경위는
[메시생성보고서](메시생성보고서.md) §4.

### (1) 법선 부호는 스캔별 센서 원점으로 정한다

재구성 품질은 법선의 안/밖이 좌우하는데, **병합된 좌표만으로는 알 수 없다.**
그 점을 어느 위치에서 봤는지가 필요하다.

→ 성과품 E57의 **스캔 블록 구조를 유지**하고 `poses_*.json`의 센서 원점을 쓴다.
점군을 하나로 뭉갠 PLY만 있으면 이 정보가 사라진다.

### (2) SDF 부호는 거리 제한 없이, 크기만 절단한다

"최근접점이 절단거리보다 멀면 바깥(+)"으로 채우면, 벽 안쪽 깊은 곳까지 바깥이
되어 **실제 표면 뒤에 가짜 표면이 하나 더 생긴다**(이중 껍질). 법선 방향이
정확히 반반으로 갈리면 이 증상이다.

### (3) 외삽 표면은 support 거리로 트리밍하되, 블록 안에서 즉시 한다

(2) 때문에 데이터가 없는 곳까지 표면이 뻗는다. 사후에 걸러도 결과는 같지만
**중간 산출물이 12배로 부푼다**(별동 5cm: 원시 2,711만 면 → 224만 면).
고해상도에서는 메모리가 버티지 못한다.

### (4) 점이 있는 블록만 순회한다

전체 격자를 훑으며 블록마다 전체 점을 스캔하면 `블록 수 × 점 수`라 해상도를
올리는 순간 폭발한다. 점을 블록 단위로 미리 담아두고 채워진 블록만 돈다.
표면은 부피가 아니라 면이라 채워진 블록은 훨씬 적다
(본체 2cm: 22.22G 복셀 중 8,593개 블록).

### (5) 블록은 경계 복셀 평면을 공유한다

블록 끝을 `i1 = i0 + block`으로 잡고 그 평면을 양쪽이 함께 포함해야 셀이
이어진다. 안 그러면 블록마다 이음매가 생긴다.
SDF 계산 시 **이웃 블록 점까지 모아야** 경계에서 값이 일치한다.

### (6) Poisson 트리밍은 밀도가 아니라 거리로 한다

Poisson 은 닫힌 표면을 만들려고 안 본 영역까지 지어내므로 잘라내야 한다.
표준 방법인 '정점 밀도 하위 N% 제거'를 LiDAR 에 그대로 쓰면, 원거리의 정상적인
면이 저밀도로 분류돼 함께 잘려나간다. 별동 실측에서 완전성 95% 가
22mm -> 1,689mm 로 악화됐다(데이터 있는 곳에 1.7m 구멍).
정확도 중앙값은 오히려 좋아 보이므로 **한 지표만 보면 속는다.**

### (7) 법선 방향은 라이브러리 규약을 믿지 말고 실측한다

skimage `marching_cubes`의 `gradient_direction`을 문서만 보고 판단했다가
반대로 나왔다. 센서 위치와 면 법선의 내적으로 **직접 측정해서** 맞춘다.
그리고 **연결 조각 단위**로 뒤집어야 한다 — 조각마다 방향이 제각각이라
전체 일괄 뒤집기로는 75%에서 멈춘다.

## 5. 만들고 나서 확인할 것

```python
import trimesh, numpy as np, json
from scipy.spatial import cKDTree
m = trimesh.load('Mesh_xxx.ply', process=False)
poses = {k: np.array(v) for k, v in json.load(open('poses_xxx.json', encoding='utf-8')).items()}
o = np.array([p[:3, 3] for p in poses.values()])

print('면', f'{len(m.faces):,}', '면적', f'{m.area:,.0f} m2')
print('퇴화면', int((m.area_faces < 1e-12).sum()))
print('중복면', len(m.faces) - len(np.unique(np.sort(m.faces, axis=1), axis=0)))
print('정점색', m.visual.kind)

rng = np.random.default_rng(0)
pick = rng.choice(len(m.faces), min(50000, len(m.faces)), replace=False)
ctr, nrm = m.triangles_center[pick], m.face_normals[pick]
_, i = cKDTree(o).query(ctr)
print('법선 바깥향', f'{(np.einsum("ij,ij->i", nrm, o[i]-ctr) > 0).mean()*100:.1f}%')
```

| 항목 | 정상 범위 | 벗어나면 |
|---|---|---|
| 퇴화면 / 중복면 | 0 | `clean_faces` 누락 |
| 법선 바깥향 | 70% 이상 | 조각 단위 정렬 미적용 (§4-7) |
| **완전성 95%** | **50mm 이하** | **트리밍 과도 — 데이터 있는 곳에 구멍** |
| 정점색 | `vertex` | 색 입히기 단계 누락 |
| bbox | 점군과 일치 | 좌표 오프셋 오류 |
| **격자를 잘게 했을 때 면적** | **줄어든다** | **늘면 트리밍 이상** (§4-3) |

마지막 항목이 헷갈리기 쉽다. 거친 격자일수록 측정되지 않은 영역까지 표면을
만들어 면적이 **부풀려진다.** 별동 기준 10cm 2,271 m² → 5cm 1,960 m² →
2cm 1,370 m²로 줄어드는 게 정상이다.
